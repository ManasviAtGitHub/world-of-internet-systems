The Edge

Cloudflare answers for more than a fifth of the web from 330+ cities using one strange trick: announcing the same IP addresses everywhere at once, so that BGP itself delivers every packet — yours, and a 31-terabit flood's — to the nearest datacenter. This episode runs the edge's three superpowers and its one spectacular failure mode: the regex that stopped 20% of the web for 27 minutes.

The world below is 12 cities standing in for 330. Latencies are proportional to drawn distance; the DDoS arithmetic uses Cloudflare's real published numbers (500 Tbps capacity, 31.4 Tbps record attack); and the regex engines in EXP-03 are genuinely implemented — the step counts are measured, not sketched.

The cache is a funnel, not a mirror

Terminating connections nearby is half the win; the other half is never bothering the origin. Each edge answers what it has cached — Cloudflare's earliest architecture already served ~75% of requests locally. But with hundreds of edges missing independently, a naive design still sprays hundreds of duplicate misses at the origin. Tiered caching turns the edge into a funnel: misses go to a regional shield datacenter first, and only shields may contact the origin — so hundreds of first-misses collapse into one.

Capacity is the DDoS strategy

Here's the beautiful accident of anycast: attack packets follow the same routes as users. A flood aimed at one IP arrives pre-fragmented across every city on Earth, each site handling a slice within local capacity, each dropping the attack fingerprints in-kernel with no human paged. Cloudflare's design doctrine is explicit: legitimate peak traffic uses a small fraction of the network's 500 Tbps, and the rest is deliberately idle armor. In December 2025 the record — 31.4 terabits per second — lasted 35 seconds and was blocked autonomously; customers mostly learned about it from the blog post.

July 2, 2019: the regex that stopped a fifth of the web

Shared fate cuts both ways. The same machinery that pushes a security rule to 330 cities in seconds — because emergent threats can't wait for a slow rollout — once pushed a WAF rule containing .*(?:.*=.*). Nested wildcards make a backtracking regex engine's work explode combinatorially, and within seconds every CPU serving HTTP traffic on every Cloudflare server was pinned at 100%. Global 502s; ~80% of traffic dropped; 27 minutes to kill — partly because the engineers' own login system ran on the burning edge. What the edge became

Once every city terminates TLS and runs filters, the next step was inevitable: run customer code there too. Containers were too heavy to put everyone's code in 330 cities, so Workers runs it in V8 isolates — the same sandbox as a browser tab: ~3 MB per tenant instead of ~35, ~5 ms cold starts instead of half a second. Cheap enough that deployment location stops being a choice; the region is Earth. The edge that began as a cache in front of your site became a programmable layer of the internet — and, as 2019 taught, a shared fate: fronting a fifth of the web trades many small failures for rare, spectacular, front-page ones.
